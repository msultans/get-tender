# get-tender

Конвейер и рабочее место для отработки тендеров. Первая площадка — **zakup.sk.kz**
(закупки группы Самрук-Казына). Дальше — остальные площадки.

Система делает то, что сейчас делается руками: сама обходит портал, скачивает
документацию по всем лотам, отсеивает неподходящие по правилам, разбирает
оставшиеся по пайплайну, считает экономику, поднимает историю закупок и
конкурентов — и будит человека только тогда, когда лот действительно стоит
внимания.

## Код

[`harvester/`](harvester/) — выгрузка тендеров: дозор, сборщик, хранилище.
Запускается на машине с доступом к порталу:

```bash
cd harvester && npm install && npm run probe
```

`probe` сам проверяет, каким способом портал отдаёт данные, и пишет отчёт.
Подробности — в [harvester/README.md](harvester/README.md).

## Статус

Спроектировано полностью, слой выгрузки написан и покрыт тестами (48 штук,
включая прогон через настоящий браузер против поддельного портала).

На живом zakup.sk.kz **ничего не проверено**: из среды разработки портал
закрыт политикой сети. Поэтому первый шаг — запустить `npm run probe` там,
где портал доступен. Он же заменяет спайк Ш-0 из [07-mvp.md](docs/07-mvp.md).
Пока probe не прогнан, числа в расчёте стоимости и бюджете задержки — оценки.

## Источник знаний

Экспертная часть (что искать в документации, как считать экономику, где прячутся
барьеры) взята из скилла `samruk-tender-analysis`, наработанного на живых
тендерах. Скилл остаётся источником правды по методике разбора; ТЗ описывает,
как эту методику превратить в конвейер.
