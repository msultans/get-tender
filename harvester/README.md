# harvester — выгрузка тендеров с zakup.sk.kz

Дозор, сборщик и хранилище. Этапы 0–1 из [../docs/02-конвейер.md](../docs/02-конвейер.md);
устройство — в [../docs/10-сбор-данных.md](../docs/10-сбор-данных.md).

```
ДОЗОР ──► СБОРЩИК ──► БАЗА ──► очередь analyze.pending ──► обработчик
```

## Важно перед запуском

Способ доступа к порталу **не проверен на живом портале** — из среды, где
писался этот код, zakup.sk.kz закрыт политикой сети. Поэтому первая команда —
`probe`: она сама прогоняет проверки и говорит, каким способом ходить.

Имена полей в API портала тоже неизвестны заранее. Разбор ищет их **по смыслу
имени** (`purchaseNumber`, `sumNoNds`, `customerNameRu` и подобные), а не по
жёсткому пути, поэтому имеет шанс заработать сразу. Если не заработает —
`probe` сложит все ответы портала в `probe-dump/`, и разбор достраивается
правкой одного списка шаблонов в `src/portal/extract.ts`.

## Установка

```bash
cd harvester
npm install
npx playwright install chromium     # если Chromium ещё не стоит
```

Нужен Node 20 или новее.

## Порядок запуска

```bash
npm run probe      # 1. проверить портал, выбрать способ доступа
npm run watch      # 2. дозор: раз в минуту первая страница списка
npm run fetch      # 3. сборщик: карточки и файлы (в другом окне)
npm run status     # что уже собрано
```

Разовый прогон без цикла:

```bash
npx tsx src/cli.ts watch --once
npx tsx src/cli.ts fetch --once
```

## Что делает probe

| Опыт | Вопрос |
|---|---|
| 0 | Есть ли на портале раздел для разработчиков или открытые данные |
| 1 | Качается ли файл обычным HTTP, без браузера |
| 2 | Переживает ли подпись выход из браузера: тот же запрос голым клиентом и с заголовками браузера |
| 3 | Откуда берётся нестандартный заголовок — вычисляется в бандле или приходит с сервера |

Вердикт — один из трёх:

| Режим | Что значит |
|---|---|
| `http` | API отвечает без подписи, браузер не нужен вообще |
| `hybrid` | Подпись из браузера переиспользуется обычным клиентом |
| `browser` | К API только через браузер; файлы всё равно качаются по HTTP |

На выходе `probe-report.json` и каталог `probe-dump/` с ответами портала.
**Значения заголовков, кук и токенов в отчёт не попадают** — только имена и
длины, чтобы файл можно было спокойно переслать.

## Настройки

Через переменные окружения, все со здравыми значениями по умолчанию —
см. `src/config.ts`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATA_DIR` | `./data` | база, файлы, профиль браузера |
| `WATCH_INTERVAL_MS` | `60000` | как часто смотреть первую страницу |
| `PORTAL_DELAY_MS` | `4000` | пауза между обращениями к порталу |
| `DOWNLOAD_CONCURRENCY` | `4` | сколько файлов качать разом |
| `HEADFUL` | — | `1`, чтобы видеть браузер |
| `LOG_LEVEL` | `info` | `debug` для подробностей |
| `PORTAL_LIST_URL` | `…/#/ext/lots` | адрес списка, если угадан неверно |

Пауза в 4 секунды — осознанно осторожный старт, а не замер. Портал отдаёт
ошибки при частых запросах; подбирать частоту надо снизу вверх.

## Устройство

```
src/
  cli.ts              команды probe / watch / fetch / status
  config.ts           настройки из окружения
  db/
    schema.sql        таблицы
    repo.ts           идемпотентная запись, дедупликация файлов
  portal/
    browser.ts        Playwright, перехват XHR, пауза, размыкание цепи
    http.ts           обычный клиент — им качаются файлы
    discover.ts       поиск нужного запроса в трафике (чистые функции)
    extract.ts        разбор полей по смыслу имени  ← сюда править
    probe.ts          проверка портала
  pipeline/
    watch.ts          дозор
    fetch.ts          сборщик
    queue.ts          очередь задач на SQLite
```

**Про SQLite.** В архитектуре записан Postgres, и на сервере будет он. Пока
задача — запуститься без возни: SQLite это один файл и ноль настройки, а на
потоке в полторы сотни лотов в сутки его хватает с запасом. Схема та же,
переезд — механический.

## Что уже проверено

48 тестов, `npm test`. Покрыто: разбор сумм, дат и статусов (включая
казахские), разбор строки списка, идемпотентность записи, определение
изменений, дедупликация файлов по sha256, очередь с ретраями и возвратом
зависших задач, маскирование секретов в отчёте, и сквозной прогон через
**настоящий браузер** против поддельного портала — перехват XHR, опознание
запроса списка, сбор строк.

Не проверено: живой zakup.sk.kz. Это и делает `probe`.
