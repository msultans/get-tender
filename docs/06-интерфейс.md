# 06. Интерфейс

**Макеты:** https://www.figma.com/design/PeOmiCXwn5BKVxhygwvmMd — страница «Экраны»,
три артборда: `01 · Лента`, `02 · Карточка тендера`, `03 · Уведомление в Telegram`.
Ниже — описание всех экранов, включая те, что войдут во вторую итерацию.

Рабочее место одного человека. Главный критерий: **на zakup.sk.kz заходить не
нужно**.

Общая рамка — левая навигация, шириной в иконки с подписями:
`Лента · Тендеры · Воронка · Задачи · Рынок · Поставщики · Правила · Настройки`

В MVP живые только **Лента** и **Карточка тендера**; остальные — во второй
итерации (см. [07-mvp.md](07-mvp.md)).

---

## Экран 1. Лента

Первое, что видно при входе. Отвечает на вопрос «что нового и что горит».

**Шапка:** счётчики по категориям — 🔥 Горячие · Интересные · Наблюдать ·
Отклонённые. Клик по счётчику = фильтр.

**Панель фильтров:** дедлайн (сегодня / 3 дня / неделя), сумма, регион, способ
закупки, тип предмета, заказчик. Плюс сохранённые наборы фильтров.

**Список карточек**, по умолчанию сортировка по баллу. Одна карточка:

```
┌──────────────────────────────────────────────────────────────┐
│ 🔥 82  АО «Заказчик» · тендер          до подачи 6 дней ⚠   │
│ Услуги по техническому обслуживанию и ремонту автотранспорта │
│ 48 500 000 ₸ без НДС · Алматы · услуга · рамочный договор    │
│                                                              │
│ Рентабельность B: 14%   Падение до: 11%   Порог демпинга ~9% │
│ ⚑ 3 скрытых требования   ? 4 вопроса, дедлайн 12.09          │
│                                                              │
│                          [Открыть]  [В работу]  [В архив]    │
└──────────────────────────────────────────────────────────────┘
```

Что даёт карточка без раскрытия: категория и балл, дедлайн с предупреждением,
тип договора (рамочный подсвечивается — это меняет всю экономику), три числа по
деньгам, количество находок и вопросов.

**Отклонённые** доступны отдельным фильтром и показывают **причину отказа** —
какое правило триажа сработало. Оттуда же кнопка «Разобрать всё равно»,
запускающая глубокий анализ вручную.

**Лента изменений** — отдельная вкладка: продления сроков, новые разъяснения,
изменения ТД по лотам, которые уже смотрели. Это не менее ценно, чем новые лоты.

## Экран 2. Карточка тендера

Главный экран продукта. Три колонки.

```
┌─────────────┬────────────────────────────────┬──────────────┐
│ ДОКУМЕНТЫ   │ ПРОСМОТРЩИК                    │ РАЗБОР       │
│             │                                │              │
│ ▸ Объявление│  ┌──────────────────────────┐  │ Вердикт      │
│ ▾ ТД        │  │                          │  │ Тип договора │
│   Раздел 1  │  │   стр. 14                │  │ Квалтребован.│
│   Раздел 3 ⚑│  │   ▓▓▓▓ подсветка ▓▓▓▓    │  │ Суть работ   │
│   Раздел 11 │  │                          │  │ Матрица      │
│ ▸ Договор   │  │                          │  │ Коммерция    │
│ ▾ ТС лот 1  │  │                          │  │ Экономика    │
│   Прил. 1 ⚑ │  │                          │  │ Запас цены   │
│   Прил. 2   │  └──────────────────────────┘  │ Рынок        │
│ ▸ ТС лот 2  │                                │ Вопросы (4)  │
│             │  [стр 14/62] [поиск] [скачать] │ Допущения (6)│
└─────────────┴────────────────────────────────┴──────────────┘
```

**Левая колонка — документы.** Дерево: файл → секции (`ТД / Раздел 3 / п. 3.4`).
Значок ⚑ на секциях, где есть находки. Файл с одинаковым md5 в разных лотах
помечается отдельно — это находка сама по себе.

**Центр — просмотрщик.** PDF.js. Открывается на нужной странице с подсветкой
цитаты. Поиск по всему комплекту документов сразу, а не по одному файлу.

**Правая колонка — разбор.** Блоки, сворачиваемые. **Каждое утверждение —
кликабельная ссылка на якорь**: клик открывает документ в центре на этом месте.
Это ключевая механика экрана.

Цветовая дисциплина:
- обычный текст — вывод, подтверждённый цитатой
- **отдельным цветом — допущения** и «чего в документах нет»
- красным — блокирующие находки (`severity: blocker`)

Наверху правой колонки — вердикт одной строкой, три главных риска и кнопки
`В работу` / `В архив` / `Отложить`.

### Блок «Квалификационные требования»

Таблица, а не проза:

| Требование | Источник | Выполнимость | Что нужно |
|---|---|---|---|
| Бокс в г. Алматы, документы в 3 р.д. | ТС п. 4.2 ⚑ | закрываем с затратами | аренда, ~X ₸/мес |
| Интеграция по API с ERP | ТС п. 6.1 ⚑ | **не закрываем** | вето V1 |

Столбец «Выполнимость» редактируется человеком — модель ставит первичную оценку,
решение за человеком. Изменение оценки пересчитывает балл и вето немедленно.

### Блок «Экономика»

Таблица финмодели прямо в приложении. Вводные (синие на жёлтом, как в xlsx)
редактируются, всё пересчитывается на месте, три сценария A/B/C — колонками.
Внизу — контрольные показатели и кнопка `Скачать .xlsx`.

Смысл: не открывать Excel ради «а что если поставщик даст на 5% дешевле».

### Блок «Рынок»

- история закупок этого предмета у этого заказчика: кто держал, каким способом,
  суммы с допсоглашениями
- участники с их статусом в РНУ и Перечне ненадёжных Фонда, значком
- оценка числа участников и разброса цен — **с пометкой, что это оценка**
- список «кому написать за ценами» по позициям спецификации

Если портал отдал не всё, вверху блока честная плашка: «данные неполные, портал
вернул ошибки».

### Блок «Вопросы на разъяснение»

Готовые формулировки, каждая с обоснованием и якорем на пункт, породивший
вопрос. Кнопки `Копировать все` и `В задачи`. Дедлайн подачи вопросов — видно
всегда, отдельно от дедлайна подачи заявки.

## Экран 3. Воронка

Канбан по стадиям: `Новый · В проработке · Готовим заявку · Подана · Итоги ·
Выиграли / Проиграли · Исполнение`.

Карточка в канбане: заказчик, предмет, сумма, ближайший дедлайн, число открытых
задач. Красная полоса, если дедлайн ближе трёх дней, а задачи не закрыты.

---

## Экран 4. Задачи и календарь

Два вида одного и того же: список и календарь.

Задачи сгруппированы по тендерам, но есть сводный вид **по типу**: все запросы
цен вместе — их удобно отправлять пачкой; все документы вместе; все обеспечения
вместе.

Задачи создаются автоматически из анализа. Человек их правит и закрывает, а не
заводит.

Календарь показывает четыре типа событий: дедлайн вопросов, дедлайн подачи,
вскрытие, ожидаемые итоги. Экспорт в iCal, чтобы события попадали в обычный
календарь.

## Экран 5. Правила

Редактирование триажа и весов скоринга **без кода**.

- жёсткие отсечки — форма с полями и списками
- веса скоринга — ползунки с немедленным пересчётом
- вето-правила — переключатели с объяснением последствий
- **предпросмотр на истории**: «при этих правилах за последний месяц прошло бы
  N лотов вместо M, вот какие добавились и какие отпали»

Предпросмотр обязателен. Без него настройка правил — гадание, а цена ошибки
здесь — пропущенный тендер.

---

## Экран 6. Поставщики

База «к кому обращаться за ценами»: контакт, компания, по каким КТРУ, история
запросов и ответов. Пополняется по ходу работы, используется на этапе 5.

---

## Мелочи, которые решают

- **Дедлайн всегда виден** — в шапке карточки, в ленте, в канбане. Это главное
  число в тендерах
- **Балл кликабелен** — раскрывается разложение по факторам, видно, что именно
  дало 82
- **История лота** — лента изменений по этому лоту: когда появился, что
  менялось, когда переразбирался
- **Всё, что оценка, помечено как оценка.** Демпинговый порог, число участников,
  цены по открытым источникам — не факты
- **Стоимость анализа** видна в настройках агрегатом за период

## Чего в интерфейсе быть не должно

- обязательных полей, которые человек заполняет ради процесса
- вердикта без объяснения
- цифры без источника
- «загрузка…» дольше секунды на ленте — она открывается первой
