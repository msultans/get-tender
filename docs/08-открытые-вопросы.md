# 08. Открытые вопросы

То, что нельзя вывести из документов или кода — только от Султана. Разбито по
срочности: блокирующее нельзя обойти, остальное имеет разумное значение по
умолчанию и правится позже.

---

## Блокирует работу

### 1. Пороги триажа

Без них триаж работает в режиме «пропускать всё», а это дорого на анализе.
Нужны конкретные значения:

- **Диапазон сумм.** Ниже какой плановой суммы без НДС не имеет смысла заходить?
  Выше какой не потянем по обороту и обеспечению?
- **Регионы.** Где работаем сами? Куда готовы зайти, если экономика хорошая?
- **Способы закупки.** Тендер, ЗЦП, что-то ещё? Где не участвуем принципиально?
- **Стоп-лист по предметам.** Что не берём никогда — лицензируемое, чужой
  профиль, обжигались.
- **Белый список.** Что берём всегда, даже при слабой экономике — свой профиль.
- **Лимит обеспечения заявки.** Сколько денег можно одновременно держать
  замороженными по всем активным заявкам?

Практичный способ: дать 10–15 лотов с портала с пометкой «этот брал бы / этот
нет / этот посмотрел бы» — пороги выведутся из них точнее, чем из чисел
по памяти.

### 2. Матрицы товар / работа / услуга

В [03-правила.md](03-правила.md) заполнен каркас по методике скилла. Нужна
проверка: что в матрицах лишнее, чего не хватает, что обязательно, а что
справочно. Это чистая экспертиза, вывести её неоткуда.

### 3. Профиль компании для квалтребований

Чтобы система оценивала выполнимость требований, а не просто их перечисляла:

- сколько лет опыта по профилю (влияет на условную скидку до −2,5%)
- статус МСБ (условная скидка −1%)
- свои помещения и в каких городах
- оснащение
- штат: специалисты, лицензии, сертификаты
- лицензии и допуски компании
- вхождение в отраслевые реестры

## Нужно до запуска в бой

### 4. Финансовые вводные для модели

- стоимость денег (ставка, по которой считаем кассовый разрыв)
- нормальная оборачиваемость: через сколько дней после акта реально приходит
  оплата
- целевая чистая рентабельность — ниже какой не заходим
- есть ли кредитная линия и какого размера

### 5. Telegram

Аккаунт для бота, куда слать. Один получатель или несколько.

### 6. Сервер

Где разворачиваем. Требования скромные: 2–4 vCPU, 8 ГБ RAM, 100+ ГБ диска под
документы (уточнится после Ш-0, когда станет известен средний размер комплекта).
Важно: **сервер должен ходить на zakup.sk.kz** — из текущей среды разработки
портал закрыт политикой егресса.

### 7. Условия использования портала

Проверить, есть ли в правилах zakup.sk.kz ограничения на автоматизированный
сбор. Если есть — скорректировать частоту или подход до запуска, а не после.

## Можно решить по ходу

### 8. Веса скоринга

В [03-правила.md](03-правила.md) стоят стартовые. Настраиваются на реальных
данных через предпросмотр на истории — гадать заранее бессмысленно.

### 9. Тихие часы

Во сколько не будить. По умолчанию 22:00–08:00, кроме «до дедлайна меньше 24
часов».

### 10. Глубина истории

За сколько лет поднимать реестр договоров для аналитики. По умолчанию 3 года.

### 11. Хранение документов

Сколько держать комплекты по отклонённым лотам. По умолчанию: текст — бессрочно
(он лёгкий и нужен для поиска), исходные PDF — 6 месяцев, потом только по
лотам, которые брали в работу.
