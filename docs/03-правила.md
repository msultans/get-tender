# 03. Правила

Всё в этом документе — **конфигурация, а не код**. Правила редактируются в
интерфейсе, версионируются, и у каждого лота хранится, какая версия правил к
нему применялась. Иначе через месяц будет непонятно, почему полгода назад лот
отклонили.

---

## Триаж

Детерминированные правила, без языковой модели. Стоимость прогона — ноль.
Порядок важен: первое сработавшее вето прекращает проверку.

### Жёсткие отсечки (REJECT)

| # | Правило | Значение по умолчанию | Комментарий |
|---|---|---|---|
| T1 | Статус лота | приём заявок открыт | Закрытые — в архив без разбора |
| T2 | Дней до дедлайна подачи | ≥ 4 | Меньше — физически не успеть собрать комплект |
| T3 | Плановая сумма без НДС | **уточнить** | Нижняя граница — ниже нет смысла; верхняя — не потянем обеспечение и оборот |
| T4 | Регион / место поставки | **уточнить** | Барьер «помещение в городе лота» делает чужие регионы дорогими |
| T5 | Способ закупки | **уточнить** | Какие способы вообще рассматриваем |
| T6 | Предмет / КТРУ в стоп-листе | **уточнить** | Лицензируемые виды, чужой профиль |
| T7 | Обеспечение заявки | ≤ доступный лимит | Считается от плановой суммы по проценту из ТД |
| T8 | Заказчик в чёрном списке | пусто | Был плохой опыт — не тратим анализ |

### Приоритеты (не отсекают, повышают место в очереди)

| # | Правило | Эффект |
|---|---|---|
| P1 | Предмет / КТРУ в белом списке | В начало очереди анализа |
| P2 | Заказчик, с которым уже работали | Бонус к скорингу на этапе 6 |
| P3 | Похожий лот уже разбирался | Переиспользование части анализа, дешевле |

**Значения «уточнить» — от Султана**, см. [08-открытые-вопросы.md](08-открытые-вопросы.md).
До их получения триаж работает в режиме «пропускать всё и логировать», чтобы
собрать статистику по реальному потоку лотов и настроить пороги на данных, а не
на догадках.

## Матрицы по типу предмета

Тип определяется на этапе 4.4. Матрица — обязательный список полей, которые
анализ должен заполнить или явно пометить как «в документах нет».

### Товар

| Поле | Что выясняем | Источник |
|---|---|---|
| Модель / SKU | По нестандартным точным значениям спецификации | ТС + первоисточник вендора |
| Реальность требований | Есть ли модель, проходящая **все** пункты | Проверка по datasheet |
| Ошибки составителя | Пункты, которые не проходит ни одна модель | Отдельным списком → в вопросы |
| Ограничители канала | Заводская казахская раскладка без наклеек, гарантия по серийному номеру на территории РК, срок гарантии сверх стандартного | ТС |
| Канал поставки | Местный дистрибьютор или импорт | Рынок |
| Срок поставки | Реальный по каналу против требуемого | ТС + поставщики |
| Таможня и сертификация | Пошлина ЕАЭС, ТР ТС 004/2011 и 020/2011, нотификация на шифрование в реестре ЕЭК | Константы + ТН ВЭД |
| Цена закупа | Минимум 3 источника | Поставщики |
| Гарантийные обязательства | Что берём на себя и сколько это стоит | Договор |

**«Мощнее» ≠ «соответствует»**: у более старшей модели может быть ниже базовая
частота или отсутствовать NPU. Проверка идёт по каждому пункту отдельно, а не
«в целом лучше».

### Работа

| Поле | Что выясняем |
|---|---|
| Объём работ | Есть ли он вообще в документах. В рамочном договоре — нет |
| Кто определяет объём | Дефектный акт? Кто и когда подписывает |
| Ресурсы | Люди, техника, допуски, аттестации |
| База в городе лота | Помещение, срок предоставления документов после подписания |
| Материалы | Чьи, наценка, кто несёт риск цены |
| Субподряд | Нужен ли, есть ли, разрешён ли договором |
| Сроки и штрафы | Реальность сроков, размер неустойки |
| Приёмка | Акты, кто подписывает, что блокирует оплату |

### Услуга

| Поле | Что выясняем |
|---|---|
| Посты и смены | Численность, график, несовмещаемые позиции |
| Квалификация персонала | Лицензии, сертификаты (включая языковые), чем подтверждается |
| Инфраструктура | Боксы, ПО, интеграция по API, VPN по политике заказчика |
| SLA | Показатели и штрафы за нарушение |
| Схема оплаты | За факт или за период. В рамочном — за факт |
| Скрытые нагрузки | Эвакуация за счёт исполнителя, оформление актов по каждому заезду, отчётность |
| Разовые работы | Интеграция, согласование доступов — стоимость на старте |

## Скоринг

Считается после этапов 4 и 5. Веса настраиваются в интерфейсе; ниже — стартовые
значения, которые заведомо придётся править на реальных данных.

| Фактор | Вес | Как считается |
|---|---|---|
| Чистая рентабельность, сценарий B | 30 | Из финмодели |
| Запас по цене | 20 | Насколько можем упасть до нуля, с учётом демпингового порога |
| Барьеры входа | 20 | Штраф за каждое требование «закрываем с затратами» |
| Прогноз конкуренции | 15 | Штраф за высокое историческое число участников |
| Кассовый разрыв | 10 | Штраф за длинную оборачиваемость и большое обеспечение |
| Знакомство | 5 | Бонус за похожий выполненный предмет или знакомого заказчика |

Категории по итоговому баллу:

| Категория | Условие | Что происходит |
|---|---|---|
| 🔥 Горячий | ≥ 75 | Уведомление немедленно |
| Интересен | 50–74 | Уведомление в дайджест |
| Наблюдать | 25–49 | Только в ленте |
| Не заходить | < 25 | В ленте под фильтром, с причиной |

### Вето-правила

Применяются **после** расчёта балла и могут только понизить категорию.

| Вето | Условие | Потолок категории |
|---|---|---|
| V1 | Хотя бы одно квалтребование оценено как «не закрываем» | Наблюдать |
| V2 | Рамочный договор без прейскуранта и без ответа на разъяснение | Наблюдать |
| V3 | Отрицательная чистая прибыль в базовом сценарии B | Не заходить |
| V4 | Комплект документов неполный (`documents_incomplete`) | Наблюдать, с явной пометкой |
| V5 | До дедлайна подачи меньше T2 дней на момент вердикта | Наблюдать |

V1 — самое важное. Невыполнение требования после подписания = риск попадания в
Перечень ненадёжных поставщиков Фонда, а это **закрытие всего рынка группы на 24
месяца**. Никакая экономика одного лота этого не окупает, поэтому вето
безусловное и снимается только человеком вручную, с записью причины.

## Финмодель

Один лист .xlsx, блоки в порядке:

**1. ИСХОДНЫЕ ДАННЫЕ ЗАКУПКИ** — суммы лотов, выбранный лот, НДС, объёмные
показатели, срок, оборачиваемость оплаты, стоимость денег, обеспечение, КПН

**2. ДОПУЩЕНИЯ ПО СЦЕНАРИЯМ** — три сценария: **A** оптимистичный (свои
мощности), **B** базовый, **C** тяжёлый

**3. РАСЧЁТ ЭКОНОМИКИ** — выручка, статьи прямых затрат, ПРЯМЫЕ ИТОГО,
финансовые расходы (замороженное обеспечение + стоимость денег в кассовом
разрыве), прибыль до налога, КПН, чистая прибыль

**4. КОНТРОЛЬНЫЕ ПОКАЗАТЕЛИ** — чистая рентабельность, себестоимость на единицу,
выручка на единицу, загрузка, точка безубыточности, **максимальное падение цены
от суммы лота**, демпинговый порог

**5. ЛЕГЕНДА** — все ключевые условия договора и ТС **с номерами пунктов**

Правила оформления:
- вводные — синий шрифт на жёлтой заливке; формулы — чёрный; в легенде это
  объясняется
- ссылки на строки исходных данных строятся **динамически по индексу**, а не
  константой — иначе КПН и подобное считается от чужой ячейки
- обязательный прогон `recalc.py` до `status: success, total_errors: 0`

## Константы (Казахстан, 2026)

| Параметр | Значение |
|---|---|
| НДС | 16% |
| КПН | 20% |
| Пошлина ЕАЭС на компьютеры и ноутбуки (ТН ВЭД 8471) | 0% |
| Ввоз радиоэлектроники в ЕАЭС | ТР ТС 004/2011 и 020/2011 + нотификация на шифрование в реестре ЕЭК |
| Курсы валют | Актуальные с nationalbank.kz, **не по памяти** |
| Условная скидка за опыт | −1,5% за 3 года, далее +0,5%/год, максимум −2,5% |
| Условная скидка МСБ | −1% |
| Максимальная условная скидка | −3,5% |
| Порог демпинга (работы и услуги) | 20% ниже среднего арифметического цен допущенных заявок |

Константы хранятся в конфиге с датой актуальности. НДС и КПН меняются
законодательно — при изменении старые финмодели не пересчитываются, а сохраняют
ставку на дату расчёта.
