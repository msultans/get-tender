# 03. Правила и таксономия

Всё в этом документе — **конфигурация, а не код**: редактируется в интерфейсе,
версионируется, и у каждого лота хранится, какая версия к нему применялась.

---

## Таксономия

Раскладка лотов по полкам. Первые два уровня жёсткие, третий — рабочий список,
который будет уточняться на живом потоке.

### Уровень 1. Категория

| Категория | |
|---|---|
| **Работы и услуги** | |
| **Товары** | |

### Уровень 2. Ценовой сегмент

По плановой сумме **без НДС** (на портале суммы даются без НДС).

| Сегмент | |
|---|---|
| до 1 млн ₸ | |
| 1–10 млн ₸ | |
| свыше 10 млн ₸ | |

### Уровень 3. Предмет

Стартовый список. Каждый лот получает ровно одну категорию; не распознанные
попадают в «прочее» и разбираются вручную — по накопленному «прочему» список
дополняется.

**Работы**

`строительно-монтажные` · `ремонт зданий и сооружений` · `ремонт оборудования` ·
`пусконаладочные` · `проектно-изыскательские` · `дорожные и земляные` ·
`электромонтажные` · `монтаж систем (ОВиК, слаботочка, пожарные)`

**Услуги**

`транспорт и спецтехника` · `ТО и ремонт автотранспорта` · `клининг и санитарное
содержание` · `охрана` · `питание` · `ИТ: разработка и сопровождение` · `ИТ:
лицензии и подписки` · `связь и телеком` · `обучение и аттестация` ·
`медицинские и медосмотры` · `страхование` · `аудит, консалтинг, оценка` ·
`аренда помещений и оборудования` · `полиграфия и реклама` · `утилизация отходов` ·
`экспертиза и лабораторные испытания` · `метрология и поверка` ·
`техническое обслуживание зданий`

**Товары**

`ИТ-оборудование и оргтехника` · `запчасти и расходники для транспорта` ·
`ГСМ и химия` · `спецодежда и СИЗ` · `мебель` · `электротехника и кабель` ·
`трубы и металлопрокат` · `насосы, арматура, промоборудование` ·
`строительные материалы` · `канцтовары и хозтовары` · `медицинские изделия` ·
`продукты питания` · `инструмент и оснастка`

### Уровень 4. Квалификационный барьер

Ключевой разрез после цены. Определяется на этапе 3.

| Барьер | Вес | Как определяется |
|---|---|---|
| **Лицензия** | главный | Регулярки по фрагменту `licenses`: СМР, проектирование, охранная, медицинская, образовательная, обращение с отходами, работа с источниками, перевозки |
| Разрешение / аттестация / аккредитация | высокий | То же |
| Членство в реестре или СРО | высокий | То же |
| Опыт: сумма или годы | средний | Раздел 3 ТД |
| Специалисты с сертификатами | средний | ТД + ТС |
| Оборудование или техника в собственности | средний | ТС |
| Помещение или база в регионе лота | средний | ТС + `deadlines` |
| Сертификаты систем менеджмента | низкий | ТД |
| Финансовые: обороты, отсутствие задолженности | низкий | ТД |

**Лицензия — первый фильтр в ленте.** Есть лицензия у нас → лот рабочий; нет →
почти всегда мимо, независимо от экономики.

## Флаг «требует внимания»

Балльной оценки нет — решение за человеком. Система поднимает флаг по одному
консервативному правилу:

```
внимание  =  сумма без НДС ≥ ПОРОГ
             И  нет ни одного квалтребования со статусом «не закрываем»
```

| Параметр | Значение по умолчанию | Комментарий |
|---|---|---|
| `ПОРОГ` | **уточнить** | Ниже какой суммы не смотрим вообще |
| Проверка выполнимости | по профилю компании | См. [08-открытые-вопросы.md](08-открытые-вопросы.md), п. 3 |

Отдельно флаг поднимается на **предварительные обсуждения** в интересных
категориях независимо от суммы: там ещё можно повлиять на техспецификацию, и окно
закрывается быстро.

Правило намеренно широкое. **Пропустить хороший лот дороже, чем показать
лишний** — сузить всегда успеем, увидев реальный поток.

Вместе с флагом хранятся причины: что сработало, что нет, какое требование
оказалось непроходимым. В интерфейсе это строка, а не число.

## Матрицы по типу предмета

Обязательный список полей, которые разбор заполняет или явно помечает как «в
документах нет». **Требует проверки** — это твоя экспертиза, я собрал каркас по
методике скилла.

### Товар

| Поле | Что выясняем | Уровень |
|---|---|---|
| Что закупается, количество, единица | Спецификация | L1 |
| Требуется ли лицензия на оборот | `licenses` | L1 |
| Срок поставки по документам | `deadlines` | L1 |
| Гарантийные обязательства | Договор | L1 |
| Модель / SKU | По нестандартным точным значениям (кэш, TDP, частоты, TOPS, ёмкость, габариты до сотых) | L2 |
| Реальность требований | Проходит ли **все** пункты хоть одна модель | L2 |
| Ошибки составителя | Пункты, которые не проходит ни одна модель | L2 |
| Ограничители канала | Заводская казахская раскладка без наклеек, гарантия по серийному номеру на территории РК, срок сверх стандартного | L2 |
| Канал поставки | Местный дистрибьютор или импорт | L2 |
| Таможня и сертификация | Пошлина ЕАЭС, ТР ТС 004/2011 и 020/2011, нотификация на шифрование | L2 |
| Цена закупа | Минимум 3 источника | L2 |

**«Мощнее» ≠ «соответствует»**: у более старшей модели может быть ниже базовая
частота или отсутствовать NPU. Проверка по каждому пункту отдельно.

### Работы

| Поле | Что выясняем | Уровень |
|---|---|---|
| Что делаем, где, в каком объёме | Спецификация | L1 |
| Лицензия или допуск | `licenses` | L1 |
| Есть ли объём вообще | В рамочном договоре — нет | L1 |
| Сроки и штрафы | `deadlines`, `penalties` | L1 |
| База или помещение в регионе лота | ТС | L1 |
| Кто определяет объём | Дефектный акт: кто и когда подписывает | L2 |
| Ресурсы: люди, техника, допуски | ТС | L2 |
| Материалы: чьи, наценка, чей риск цены | Договор | L2 |
| Субподряд: нужен, есть, разрешён ли | Договор | L2 |
| Приёмка: акты, кто подписывает, что блокирует оплату | Договор | L2 |

### Услуги

| Поле | Что выясняем | Уровень |
|---|---|---|
| Что за услуга, где, как часто | Спецификация | L1 |
| Лицензия или допуск | `licenses` | L1 |
| Численность, посты, смены | ТС | L1 |
| Схема оплаты: за факт или за период | `payment_terms` | L1 |
| Квалификация персонала и чем подтверждается | ТС | L2 |
| Инфраструктура: помещения, ПО, интеграции, VPN | ТС | L2 |
| SLA и штрафы за нарушение | Договор | L2 |
| Скрытые нагрузки | Эвакуация за свой счёт, акты по каждому обращению, отчётность | L2 |
| Разовые работы на старте | Интеграция, согласование доступов | L2 |

## Финмодель (уровень L2)

Один лист .xlsx, блоки в порядке:

1. **ИСХОДНЫЕ ДАННЫЕ ЗАКУПКИ** — суммы лотов, выбранный лот, НДС, объёмные
   показатели, срок, оборачиваемость оплаты, стоимость денег, обеспечение, КПН
2. **ДОПУЩЕНИЯ ПО СЦЕНАРИЯМ** — **A** оптимистичный (свои мощности), **B**
   базовый, **C** тяжёлый
3. **РАСЧЁТ ЭКОНОМИКИ** — выручка, прямые затраты, ПРЯМЫЕ ИТОГО, финансовые
   расходы (замороженное обеспечение + стоимость денег в кассовом разрыве),
   прибыль до налога, КПН, чистая прибыль
4. **КОНТРОЛЬНЫЕ ПОКАЗАТЕЛИ** — чистая рентабельность, себестоимость и выручка на
   единицу, загрузка, точка безубыточности, **максимальное падение цены**,
   демпинговый порог
5. **ЛЕГЕНДА** — ключевые условия договора и ТС **с номерами пунктов**

Оформление:
- вводные — синий шрифт на жёлтой заливке, формулы — чёрный, в легенде это
  объясняется
- ссылки на строки исходных данных строятся **динамически по индексу**, не
  константой — иначе КПН считается от чужой ячейки
- обязательный прогон `recalc.py` до `status: success, total_errors: 0`

## Упрощённая экономика (уровень L1)

Пять чисел и одна строка вывода — см. [02-конвейер.md](02-конвейер.md), п. 4.5.

**Нормативы себестоимости по категориям** — настройка, стартовые значения нужны
от тебя. Пока их нет, L1 показывает только сумму, обеспечение и условия оплаты, а
поля маржи помечены как «норматив не задан». Показывать выдуманное число хуже, чем
не показывать никакого.
